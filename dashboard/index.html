❓ What does everything on this dashboard mean?

Top summary cards

Trust — the hardware-attestation level the Darkbloom coordinator has assigned this Mac. hardware means it's eligible to actually receive inference traffic; self_signed means it's online but not yet trusted enough to be routed any jobs. A drop from hardware-level triggers a macOS notification and a red banner automatically.

Daemon — whether the `darkbloom` background process itself is running, and (read straight from the daemon's own live state file) whether it's currently idle/warm or actively serving a request right this second (pulsing dot).

Requests — requests served and tokens processed since the daemon last (re)started. This resets on every restart, so it's not a lifetime total.

Warm models — how many models are currently loaded in memory (instant response) vs. how many are downloaded to disk in total.

Accumulated electricity cost and Net — see the calculation explainer under the cost/revenue chart further down for the exact formula.

Live Power gauges

CPU / GPU / Total — instantaneous power draw read straight from `powermetrics`, sampled ~5 times per second. "Total" adds a fixed 7W estimate on top for everything `powermetrics` can't see (RAM, disk, fans, PSU losses) — real wall power is somewhat higher than shown.

RAM used — system-wide memory pressure, not just this app's usage. Turns red/orange as it approaches full, since that's the exact condition that caused real model-load failures during testing.

Utilization (last hour) — % of the last ~60 minutes (in 5-minute slices) that actually saw new requests arrive, based on the real request counter. A low or 0% reading with a healthy Trust/Daemon status just means genuinely no traffic right now, not a fault — the fan being quiet is expected in that case.

Darkbloom Account (real payout vs. our own estimate)

Real jobs/tokens/payout per model, pulled directly from Darkbloom's own API every 30 seconds - the same device token `darkbloom login` already stores locally, no browser step needed. The "Darkbloom gap" column compares what this dashboard's own rough flat-rate guess would have paid for the same tokens against what Darkbloom's ledger actually paid — it is not an official platform fee or a claim about Darkbloom's pricing. It's just a check on our own estimate's accuracy, and our simplistic single blended rate (not split by input/output pricing) is probably the thing that's actually off.

Nerdy Stats

Average prompt/completion length is computed from the same real earnings entries as the Account panel above, excluding base_reward floor-payment rows (which always carry zero token counts and would otherwise skew the average toward zero). Request duration is not data from Darkbloom at all - it doesn't expose timing anywhere - so a background thread here watches the daemon's own inference_active flag flip on and off, twice a second, and logs how long each "on" window lasts. It only starts counting from whenever this dashboard first started running, and can undercount requests shorter than the check interval. GPU memory active/cached and KV-backend/MTP settings come straight from the daemon's own state file. Health checks are `darkbloom doctor`'s own findings, refreshed every 5 minutes since doctor makes a real network call - anything doctor reports as a FAIL also shows up as a banner at the top of the page (shown as a caution, not a confirmed outage, since this exact check has been observed to be wrong before). Note: neither this dashboard nor Darkbloom's API expose actual prompt or response text anywhere — only token counts, which is what's shown.

Warmup

Periodically sends a tiny request to the provider's local endpoint to keep the active model loaded in memory, so it's ready instantly instead of needing to reload when the first real request of the day arrives.

Disk Usage

Every model `darkbloom` has downloaded, with size and whether it's the one currently active. Models not currently in use get a one-click "copy remove command" — this dashboard never deletes files itself, it only prepares the exact command for you to run.

Charts

Power history — the same wattage as the live gauges, logged every 5 minutes so you can see trends over hours/days. Once there's enough history to need downsampling, a faint dashed "peak" line appears alongside the average — the highest single reading inside each plotted bucket, so brief spikes stay visible even when hundreds of raw samples are compressed into one line.

Electricity cost vs. estimated revenue — running totals over time; see its own "How is this calculated?" details below the chart for the exact formula.

Net (Revenue − Cost) Over Time — the same figure as the Net summary card, plotted over time instead of just showing the current number, so you can see whether it's trending up or down.

Ollama indicator

Flags when Ollama has a model loaded in memory at the same time, since that competed for RAM with the Darkbloom provider and caused real crashes during testing on this 48GB Mac.

How is the kWh price and Net figure calculated?

Electricity price: fetched live from elprisetjustnu.se (Sweden, zone SE3), re-checked every 15 minutes - it's the actual spot price for the current hour, not an estimate. The source is Swedish SEK; this dashboard converts to USD (checked hourly) so everything on the page shares one currency.

Cost so far: every 5 minutes, measured power draw (CPU+GPU from powermetrics, plus a fixed 7W baseline guess for RAM/disk/fans/PSU loss that powermetrics doesn't see) is converted to the energy used in that 5-minute slice, then priced at that slice's own USD/kWh rate. Those slices add up into the running "Accumulated electricity cost" card and the cost line on this chart.

Estimated revenue: Darkbloom's alpha pricing is roughly $0.05/M input tokens + $0.20/M output tokens; since darkbloom status only reports a combined token count (not split input/output), this uses a blended midpoint of $0.125/M tokens as a rough stand-in - already USD-native, no conversion needed.

Net (estimated) = Estimated revenue − Accumulated electricity cost. This is our own guess built from local numbers, not what Darkbloom actually paid - once the account is synced (see the Darkbloom Account panel above), "Net (real balance)" replaces it with your real ledger balance instead.
